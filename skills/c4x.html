The brief

01

A fixed format that reads well in a pull request. Each element, relation and flow step is one line with fields separated by |; attributes go underneath.

  • Unknowns are written as ? and collected as open questions. The agent doesn’t fill them in.
  • Planned changes are a diff: + adds, ~ changes, - removes, per dated phase.
  • Section names and keys are English; names and descriptions can be in any language.

Planning layers on plain C4

02

Every extension is a tag or c4x_* metadata on an ordinary C4 element, so the model stays valid C4 and a strict export drops them cleanly.

As-is and to-be, from one model

03

The model keeps today’s architecture and marks each planned change with phase_new, phase_changed or phase_removed. Each phase gets its own view, filtered from the same source, so the current and future diagrams can’t drift apart.

This is what LikeC4 itself renders for the Q1 2027 view of the example: the new Vector DB in green, the changed retrieval service in amber, the removed batch job gone.

Rendered by LikeC4 1.60.0 from the recs.c4 file the skill produced.

Flows with a latency budget

04

Each flow becomes a C4 dynamic view. Steps carry their expected latency; the skill adds up the synchronous path and warns when it exceeds the flow’s budget or the entry service’s p99.

Deployment

05

Nested deployment nodes, from region to cluster to instance, with replica counts and instance types written in the brief by indentation.

How the skill works

06

  1. Read the input

    A brief, meeting notes, an RFC, an existing .c4 or .dsl, or the repository itself.

  2. Draft the brief

    Gaps become ? plus an open question. You confirm before anything is generated.

  3. Lint

    17 rules in three levels: errors that block, warnings that break C4 practice, suggestions.

  4. Generate and validate

    LikeC4 files, then npx likec4 validate. A model that doesn’t parse isn’t handed over.

  5. Views and report

    Context, containers, components, each flow, each environment, each phase. Then the files, lint results and open questions.

Notes

08

Language

The skill instructions and spec are in Portuguese (pt-BR) for now. Format keywords are English and briefs can be written in any language. An English translation is planned.

Structurizr

The Structurizr DSL mapping ships with the skill but hasn’t been validated against Structurizr yet. LikeC4 output is validated with LikeC4 1.60.0.

Example data

The recommendation platform in the screenshots is fictional: teams, numbers and ticket IDs are illustrative.
